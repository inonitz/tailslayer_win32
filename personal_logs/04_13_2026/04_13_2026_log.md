### Compiling llama.cpp

I mentioned in the previous days' post that I did not want to compile llamacpp from scratch,  
but it wasn't that bad - I just had to make sure there are *NO AVX2 Instructions* were being generated, and I was ready to run it  

Before I show you how I did it, I do have to mention that their official build instructions are very good and easy to understand.  
**[Official llama.cpp Build Instructions](https://github.com/ggml-org/llama.cpp/blob/master/docs/build.md)**  
Finally, This is my setup process for building from scratch on AMD Radeon Cards with ROCM (On windows atleast):

* Install [ROCM](https://rocm.docs.amd.com/projects/install-on-windows/en/latest/install/install.html) from AMD's Website  
  *I'm running this on windows, you should have an easier time on linux*

* Add ```ROCM_BIN_PATH``` To environment variables  
  This variable will be set to something like this:  
  
  ```sh
  PS swapgs> echo $env:ROCM_BIN_PATH
  <your_full_rocm_folder_path>\Core\6.4\bin
  ```

  *make sure to close & re-open whatever terminal you were using s.t the Environment Variables (```PATH```, etc...) will refresh*

* Open a new Powershell window

* Run the following commands:

  ```sh
    $env:PATH="$env:ROCM_BIN_PATH;$env:PATH"
  ```
  
  We're manually adding ```ROCM_BIN_PATH``` as the first string inside ```PATH```  
  The ROCM Installation has a local clang toolchain with lots of libraries to compile code for compute workloads,  
  and we want that detected first

  ```sh
    git clone https://github.com/ggml-org/llama.cpp
    cd llama.cpp
    cmake -S . -B build -G Ninja -DGPU_TARGETS=gfx1100 -DGGML_HIP=ON -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++ -DCMAKE_BUILD_TYPE=Release -DCMAKE_C_FLAGS="-O3 -march=native" -DCMAKE_CXX_FLAGS="-O3 -march=native"
  ```

  There is a lot to unpack inside this cmake configuration command:
  * ```-S .``` - Specify that the source directory is the current working directory
  * ```-B build``` - Specify the directory where the sources will be built as ```$cwd/build```
  * ```-G Ninja``` - Tell cmake to generate ```.ninja``` files for compilation.  
  I didn't mention I have a local installation of the [ninja build system](https://ninja-build.org/) added to my ```$env:PATH``` variable  
    Ninja is very useful and extremely fast at compilation
  * ```-DGPU_TARGETS=gfx1100 -DGGML_HIP=ON``` - I'm compiling only for the HIP Backend, specifically for ```gfx1100``` Class Cards
    This information is ripped straight from the **[HIP Section](https://github.com/ggml-org/llama.cpp/blob/master/docs/build.md#hip)**

  * ```-DCMAKE_C_FLAGS="-O3 -march=native" -DCMAKE_CXX_FLAGS="-O3 -march=native"``` - As the AI Says, this is the *Secret Sauce*  
    Other than overriding the CMAKE_* flags manually on the command line, I have no way of ensuring AVX2 Instructions aren't being generated, See this [Stackoverflow Answer On ```march=native```](https://stackoverflow.com/q/52653025) for more info  
    (`-O3` is just more aggresive optimization than the normally used Release `-O2` flag)

  ```sh
  cmake --build build -j ($env:NUMBER_OF_PROCESSORS/2)
  ```

  This will start building the project at ```$cwd/build``` concurrently with half the amount of threads available on the system

* Now that you started compiling the project, **Pray to god that the compilation doesn't fail**

* If you passed the step above, you're in good hands. the build artifacts will be inside ```llama.cpp/build/bin```

### My local llama.cpp setup

I won't bore you too much with the details, but the gist is that I made a ```models.ini``` file for all of my models,  
and I interface with them through a ```config.yaml``` inside continue.dev

Here are the dry details after a long day of experimentation:  

The command to run the server:

```powershell
cd llama.cpp/build/bin
.\llama-server.exe --port 5001 --models-preset models.ini
```

*Do note that your models won't load instantly, but will wait for input from local connections (i.e they'll be on-standby/on-demand)*
